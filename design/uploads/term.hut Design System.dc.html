09

Voice and rules

Do
  • Write in the README's voice: precise, technical, reasons stated, tradeoffs named.
  • State mechanisms, not benefits — the FIFO, the NDJSON stream, the 5.4 MB dmg.
  • Say what the app declines to do and why.
  • Keep the mark's peach for one action per view.
Never
  • Invent users, download counts, testimonials, press or benchmarks. None exist.
  • Imply a Homebrew tap, an Intel build, or a public source mirror.
  • Ship a light appearance without deciding it as a product question first.
  • Floating device art, perspective mockups, or a light hero — the identity is dark.
  • Gradients beyond the three approved in §10. No hue-shifting washes, no gradient text.

Gradient

three approved treatments — everything else stays flat

Three treatments, approved 2026-08-15. All stay inside the existing ladder: no new hues, nothing above 10% alpha, and each still reads as a flat dark page at a glance. Anything not on this list is out. All three are live on this page: A as the ground, B behind the masthead, C on the §07 feature cards.

mantle → crust, 180deg
AGround fade

A 3% lightness drift down the page, mantle settling into crust. Existing tokens, no hue. Gives a long page a horizon without anyone naming it a gradient — and leaves the top light, where the hero bloom sits.

term.hut
BHero bloom

Peach at 10%, radial from the top edge, behind the mark only. Once per site, on the home hero. The one place a gradient is doing real work: it puts light behind the logo.

A 1px border that runs overlay0 → surface0 top-left to bottom-right, so a feature card catches a little light. Greys only. Replaces the flat hairline on cards, nowhere else.

Motion

the app runs three perpetual loops; the site runs none
Durations and easing
120msColor and border on hover. The default; if in doubt, this.
180msDisclosure — changelog detail, docs section, copy acknowledgment.
240msThe mobile nav sheet, and nothing else.
cubic-bezier(.2 0 .2 1)Everything. One curve for the whole site.
no delayNothing waits before it starts. Staggered reveals are scroll animation in disguise.
What may move
  • Color, border-color, opacity, and the 1px active translate.
  • Height on a disclosure the user opened.
  • The one spinner on the release-feed fetch — it is the only thing saying a request is in flight.
What never moves
  • Anything triggered by scroll position: entrances, parallax, counters, pinning.
  • Page transitions. A link navigates.
  • Autoplaying video or looping product animation.
Reduced motion — inherited from index.html

Under prefers-reduced-motion: reduce the site collapses every duration to 0.01ms and every iteration count to 1, exempting the in-flight spinner — a frozen spinner reads as a hang, which is worse than the motion. That is the app’s policy verbatim; the site does not get a second opinion on it.

One finding, applied

The original label color, ctp-overlay1, measures 4.33:1 on a card. Every eyebrow label and spec annotation here is 11px, which needs 4.5:1 — so it failed. --ink-dim is now ctp-overlay2, hsl(228 17% 64%), at 5.88:1, applied across this page. Overlay1 is demoted to decoration: comment text in a code block, 1px marks, disabled labels. The app keeps overlay1 for its own labels because they sit at a different size on a different ground; the site does not inherit that one.

Delivery budget

the dmg is 5.4 MB; the homepage must not embarrass it
Ceilings
Home, first load≤ 400 KB total, images included.
Docs page≤ 150 KB after the font is cached.
WebfontsOne family, three weights, woff2, latin subset. Maple Mono only.
JavaScript≤ 15 KB, and the site works without it. No framework, no hydration.
ScreenshotsAVIF or WebP, ≤ 200 KB each, width-capped at 2x the layout slot.
RequestsUnder 20 on any page.
How that is met
  • Static HTML, hand-written or generated at build. Nothing renders client-side.
  • Icons inline as SVG — no sprite request, no icon font.
  • One stylesheet. No CSS framework, no utility layer shipped unused.
  • JS is only ever progressive: the copy button, the mobile sheet, the releases fetch. Every one degrades to something that still works.
  • No third-party embeds. Nothing loads from a domain that is not ours.

Same principle as the app: weight is a feature, and every addition is measured against it.

Privacy and legal

no data collected — which is worth saying plainly
Privacy page · the whole page
Privacy
This site collects nothing. No analytics, no cookies, no third-party scripts, no server logs kept beyond what the host needs to serve a file.
The app is the same. term.hut talks to your machine, your hosts over your own SSH, and the Claude Code CLI you already installed — using your credentials, which it never sees. Nothing is sent to us, because there is no us to send it to.
Downloads are served by GitHub Releases, which keeps its own logs.

Four sentences, no headings, no legalese scaffolding. For this audience the credibility is in the brevity — a two-thousand-word privacy policy is itself a claim, and not a good one. The one honest caveat (GitHub’s logs) is stated rather than buried.

Standing calls
AnalyticsNone. Decided. Any future measurement changes this page first.
CookiesNone, so no banner. A cookie banner on a site with no cookies is a tell.
FontsSelf-hosted. A font CDN is a third party that sees every visitor.
ReleasesGitHub. Named on the privacy page rather than treated as invisible.
LicensePlaceholder: proprietary, free to download, no source. Source is private and the releases repo is assets-only, so that is what is true today — confirm before it ships.

The vendored dependencies carry their own licenses (xterm.js, CodeMirror, Rough.js, perfect-freehand, Catppuccin icons, Maple Mono under OFL). The license page lists them; the app already vendors each with a README naming its version.

Vocabulary

the words a second writer gets wrong
Use Not Why
term.hut Term.hut, TermHut, term.hut™ Lowercase, with the dot, even at the start of a sentence.
a workspace an IDE, an editor, a terminal app The product noun. It is a terminal first, but what you get is a workspace.
project anchor, anchored directory, folder The repo bound to its session, terminal, editor and branch.
persistent detached, background, long-running Sessions that outlive the window. “Persistent” is the promise; “background” implies lesser.
agent assistant, bot, copilot, the AI The running thing doing work.
Claude the model, the LLM Name it directly. It is the Claude Code CLI you already installed.
session conversation, thread, chat The transcript and its state — not the actor. The agent has a session.
pane panel, window, tab Terminal, editor and Claude are panes in one window.
remote / over SSH cloud, hosted, server mode A remote project is not a lesser mode, and nothing here is hosted.
you the user, developers, one Second person throughout. The reader is the person at the terminal.
we HutsonLabs (as a subject), the team First person plural for decisions and intent. Sparingly — mechanisms rarely need an author.
Never write
seamless powerful supercharge effortless AI-powered revolutionary blazing fast game-changing unleash simply

If a sentence needs one of these to work, the sentence has no mechanism in it. Replace the adjective with the thing that makes it true.

Collision with the repo

Two of these overrule the code. The repo says anchored workspaces and detached agents — in README.md, PRODUCT.md, two docs filenames, and the UI’s own strings.

Since §18 derives docs slugs from those filenames, the site would read “project” and “persistent” while its URLs and the app both say otherwise. Pick one: rename in the repo (docs filenames, with redirects), or keep the repo’s words as the technical terms and use yours only in marketing copy.
