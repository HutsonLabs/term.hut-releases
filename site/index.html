term.hut

A calm agentic workspace

Terminal, files, code editor and chat share state in one window — against a local directory or ssh. Sessions run behind a FIFO on the host that owns them, so closing the app detaches instead of killing them.

Why it exists

stated as mechanisms, not benefits
01

Confusion

I kept getting confused when running multiple agents and repos: what was running where? I tried other apps, but they all had limitations that didn't work for me. I found I was using VSCodium the most, but it felt bloated. It inspired this app.

02

Curiosity

Could I design an app that met my criteria while also learning about Rust and Tauri? Could I keep it small, but useful? Could I use this for my business, personal, and technical amibition? I'm still trying to answer that question, but this is my start.

03

Claude

VSCodium paired Claude Code awesome harnesses. I wanted something smaller with only the stuff I found awesome or interesting. I try and keep it up to date with the latest from Claude Code to leverage any cool new stuff or avoid breaking anything.

Reuse, not remake

The build small by letting better tools do their thing. Also, term.hut works with Claude's subscription (important to me) and the same jsonl used with the .VSIX Anthropic release to reduce the likelihood of getting blocked.

What I won't do
  • Take your data.
  • Build for architectures I don't use.
  • Try to take over the world

In the window

the panes, and what the chat knows
about these images

Every image below is rendered from the interface mockups these surfaces were built against, using the app's own stylesheet — not a photograph of a running build. The agent names, paths and numbers in them are examples.

context · what this agent knows

The files the session actually read

One panel lists the anchor's memory, the CLAUDE.md chain, and the skills, hooks and MCP servers the session started with. Every row is a file on the host that owns the session — local anchor, local file; ssh anchor, remote file — and opening one opens that file in the editor pane. term.hut surfaces the CLI's own files and implements no memory of its own.

composer · slash commands

Whatever the CLI advertises, the composer completes

Type / and the composer completes against the command list the CLI sends in its own init message — skills, project commands, plugins. Install a skill and it is in the list next session; nothing here is hardcoded. Tab completes the token without running it, ⌘↵ opens the SKILL.md behind a row in the editor.

03

The fleet

read from ~/.term-hut/agents — no attach needed
⌘⇧A · fleet palette

Every agent, on every host you know

One keystroke over whatever panel is up. The list is read out of the agent dirs on this Mac and over SSH — working, waiting on you, finished, exited — without attaching to anything. ↵ attaches, so a session stalled on a permission prompt is one keystroke from unblocked.

the unit · agent cards

One card per agent dir, six faces, one size

State changes the badge and the tinted left border, never the layout, so twenty agents stay scannable. Each card carries a five-line window onto the most recent tool calls, read from the same transcript tail the state is derived from; the model, effort and permission mode it was launched with; and ring gauges for context and for the 5h and weekly windows. Clicking one opens a scrollable details overlay.

⌘⇧D · fleet dashboard

The whole fleet, over the workspace

A panel over the panes rather than a window of its own: one flat grid of every agent on every host, the ones needing you sorted first, remote ones marked rather than separated. A filter over label, cwd and host; state chips that carry their counts; the account's 5h and weekly rings; and a launcher. The list toggle folds each card to one aligned row when the fleet is long.

launch · new agent

The dialog prints the command it is sugar over

Where — a host and a recent workspace. What — a prompt, with a label suggested from it. How to run — model, effort, permission mode, in the composer's own order. And when: now, or on a schedule, which is cron on that host calling the same command. The exact hut agent run line sits above the launch button, because the agent outlives the window that started it.

unattended · hut agent run

An agent that starts with no app running

The same command from a shell or a crontab spawns a detached agent with term.hut nowhere in the picture; cron on the host is the whole scheduler. The run writes an ordinary agent dir, so every device that can reach that host discovers the finished work — the notification, the diff and the transcript are there the next time you open the app.

hygiene · housekeeping

The worktrees an agent leaves behind

Agents that work in .claude/worktrees/ leave trees and branches after they exit, and an uncommitted one outlives the run that made it. The broom sweeps every repo a live or recent agent touched, on this Mac and over SSH, and triages what it finds: clean and fully merged is pre-checked and removed with git worktree remove plus a branch delete — never --force, never -D. A dirty worktree is re-checked at removal time and refused whatever the caller asked for. A repo the sweep could not read is listed as an error rather than left out.
